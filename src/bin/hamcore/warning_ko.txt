IMPORTANT NOTICES ABOUT COMFYCONNECT VPN

ComfyConnect VPN provides powerful, encrypted network communication. Used correctly it gives your team secure access to company resources from anywhere. Used carelessly it can expose a private network to the internet. Please read these notices before deploying.


1. VPN Communication Protocols

1.1. Supported protocols
ComfyConnect VPN Server accepts connections over its native VPN protocol as well as OpenVPN, L2TP/IPsec, and MS-SSTP. Employees can therefore connect using the VPN client built into Windows, macOS, iOS and Android, or with a standard OpenVPN application. No ComfyConnect-specific software is required on an employee's device. The native protocol encapsulates Ethernet frames inside an HTTPS connection, so it works through firewalls that block traditional VPN traffic.

1.2. Encryption and server identity
All VPN sessions are encrypted with TLS, and you choose the cipher suite. Install a certificate issued by a trusted certificate authority on the server before putting it into production. The certificate generated automatically at installation is self-signed: it encrypts traffic, but it cannot prove the server's identity, so clients will warn about it.

1.3. UDP acceleration
For performance, sessions may carry data over UDP in addition to TCP. This traffic is encrypted. If your network policy forbids it, UDP acceleration can be disabled per Virtual Hub.


2. Software Components

2.1. ComfyConnect VPN Server
Install on a server your employees can reach. Publish only the ports you actually need, and keep the management port restricted to administrators.

2.2. ComfyConnect VPN Client
Optional. Employees may instead use the VPN client already built into their operating system.

2.3. Virtual Network Adapter
Installing the client adds a virtual network adapter to the computer. It is removed when the software is uninstalled.

2.4. Uninstallation
Uninstall from Windows "Apps & features". Uninstalling removes the virtual adapter and the service, and stops all VPN communication from that machine.

2.5. Windows Firewall
The installer registers the exceptions the software needs. If you use another firewall, allow the ports you have configured.


3. Network and Privacy

3.1. No external services are contacted
This build does not use dynamic DNS, NAT traversal relays, cloud relay services, or online update checks. A ComfyConnect VPN Server communicates only with the clients that connect to it and with any servers you explicitly configure. Nothing is reported to the vendor or to any third party.

3.2. Reachability is your responsibility
Because no relay service is used, the server must be reachable by your employees: give it a public address or a port forward, and point a DNS name at it.

3.3. Data handled by the server
The server stores its configuration, user accounts, and — if you enable them — connection logs, on the server itself. Logging is under your control. If you operate in a regulated environment, review your log retention settings and consider forwarding logs to your own SIEM.

3.4. Your legal obligations
You are responsible for operating this software lawfully in your jurisdiction, including any obligations regarding telecommunications, data protection, and employee monitoring. Configure only the access your users are authorised to have.


4. Security Recommendations

  * Set a strong server administrator password, and a separate password for each Virtual Hub administrator.
  * Replace the self-signed certificate with one from a trusted certificate authority.
  * Restrict the management port to trusted networks; do not expose it to the internet.
  * Give each client company its own Virtual Hub so tenants stay isolated from each other.
  * Use security policies and access lists to limit what each employee can reach.
  * Enable logging if you need an audit trail, and keep the host operating system patched.
